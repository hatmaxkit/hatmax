## Delivered Behavior

- `TLS=true` requires implicit TLS before the SMTP greeting. When both TLS flags are true, implicit TLS satisfies encryption without a second upgrade.
- With implicit TLS disabled, `StartTLS=true` requires the server to advertise and successfully negotiate STARTTLS before authentication or delivery. Missing or rejected upgrades fail without sending AUTH, MAIL, or DATA.
- With neither flag set, advertised STARTTLS remains opportunistic; otherwise plaintext is permitted. A failed advertised upgrade never falls back to plaintext. Both encryption paths verify certificates against Host and system trust roots unless InsecureSkipVerify is explicitly enabled.
- The complete transport transaction has a total 30-second limit. Shorter caller deadlines take precedence. Cancellation closes the connection and interrupts blocking operations, with errors discoverable through errors.Is for context.Canceled and context.DeadlineExceeded.
- Sender normalization, envelope recipients, MIME serialization, public signatures, configuration fields, and runtime settings remain unchanged.

## Contracts and Ownership

SMTP owns a net.Dialer.DialContext connection, a socket deadline, and cancellation-triggered closure registered through context.AfterFunc. Implicit TLS uses HandshakeContext; the same socket deadline and cancellation closure also bound the standard SMTP STARTTLS path. A small delivery helper retains AUTH, MAIL, RCPT, DATA, and QUIT sequencing. All exit paths close transport resources.

The opportunistic upgrade behavior follows [Go's SMTP transport](https://pkg.go.dev/net/smtp#SendMail). The implementation was checked against the local Go 1.26.7 standard library. No dependency, retry loop, new configuration surface, or long-lived watcher goroutine is added. The mailer reference, package usage, Godoc, and Unreleased entries document the resulting contract.

Cancellation or an error after DATA does not prove that the remote server rejected delivery. The mailer does not automatically retry uncertain deliveries.

## Validation

All Go checks used Go 1.26.7. Repository database tests used an isolated native PostgreSQL 18.6 cluster on loopback, stopped after validation. SMTP tests used local TCP/TLS servers, ephemeral self-signed certificates, and synthetic credentials. No external email was sent; this is not live-provider acceptance or CI evidence against PostgreSQL 16.

- Before the fix, `go test ./mailer -run '^TestSMTPEncryption$/^required_unavailable$' -count=1` failed because STARTTLS-required delivery succeeded in plaintext.
- Before the fix, `go test ./mailer -run '^TestSMTPCanceled$' -count=1` failed because a canceled send returned success.
- `make check`: passed licensing, formatting, vet, all tests, coverage, and strict lint. Total coverage: 81.3%; mailer: 86.0%.
- `make docs-check`: passed.
- `go test -race ./mailer -count=20`: passed all 20 repetitions on the final code.
- `git diff --check`: passed.

Named cases cover required, optional, unavailable, and rejected STARTTLS; implicit TLS; both flags; certificate rejection on both TLS paths; explicit verification opt-out; sender preservation; pre-canceled callers; and cancellation during greeting, EHLO, implicit/upgrade handshake, authentication, DATA entry, DATA acknowledgement, and QUIT. A short caller deadline also interrupts DATA acknowledgement. The default 30-second limit is enforced by the transport context and socket deadline; tests do not wait for that full limit.

An initial lint attempt hit temporary-storage quota; subsequent checks used task-local temporary storage without changing host configuration. The cancellation fixture accepts connection reset as well as EOF because closing a socket with unread TLS bytes can reset the peer. Final lint and repeated race tests passed.
