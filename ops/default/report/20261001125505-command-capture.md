## Delivered Behavior

- Repository validation and application staging continuously drain combined stdout and stderr without retaining an unbounded buffer. Output at or below 8 KiB is preserved; longer output retains its beginning and end, with an `[output truncated]` marker included in the 8 KiB budget.
- Capture consumes every write, including discarded bytes, so exceeding the budget does not cause a short-write error or stop pipe draining. Exit status, command ordering, working directories, staging `GOWORK=off`, and command-context cancellation are unchanged.
- Staging test infrastructure classification scans bounded stream windows, including the discarded middle and markers split across writes. The existing marker policy remains unchanged. Successful staging commands still retain no output; ordinary failures still stop validation, while infrastructure-incomplete results allow subsequent commands to run.
- The generator reference and Unreleased describe bounded capture. The chat surface remains concise; this change does not expose command output or stack traces in conversation.

## Ownership and Bounds

One private capture owns each command's output. Both stdout and stderr share its pointer, relying on the [Go Cmd writer contract](https://pkg.go.dev/os/exec#Cmd) to serialize writes; the local Go 1.26.7 source was also checked. Capture is read only after Run returns.

Retained storage has an 8 KiB head backing allocation, a fixed-size tail allocated only on overflow, and a 64-byte infrastructure scan carry. Scan windows are bounded to 8 KiB plus that carry. Memory retained by this capture is independent of total output volume; this is not a whole-process memory or runtime limit. Evidence is byte-bounded, as before.

No public API, dependency, configuration, timeout, process-group behavior, or concurrency policy was added. Existing infrastructure classification remains broad; its refinement belongs to the separate review finding, not F16.

## Validation

All Go checks used Go 1.26.7. Repository database tests used an isolated native PostgreSQL 18.6 cluster on loopback, stopped after validation. Compilation scratch and the successful database cluster were task-local under ignored `.tmp`; this is local evidence, not authenticated Codex acceptance or CI against PostgreSQL 16.

- Before the fix, `go test ./generator/execute -run '^TestCommandCapture$' -count=1` failed: repository evidence exceeded its nominal budget and lost the final summary; staging retained over 2 MiB without a truncation marker.
- `make check`: passed licensing, formatting, vet, all tests, coverage, and strict lint. Total coverage: 81.5%; generator/execute: 78.4%.
- `make docs-check`: passed.
- `go test -race ./generator/execute -run '^(TestOutputBudget|TestOutputInfrastructure|TestCommandCapture|TestCaptureCanceled)$' -count=20`: passed all 20 repetitions.
- `git diff --check`: passed.

An initial documentation compile and database-test run encountered the machine's `/tmp` quota. Repeating with task-local compilation scratch and a fresh task-local PostgreSQL cluster passed; no repository code change or shared-cache cleanup was required for that environmental failure.

Named cases cover empty, short, exact-budget, and overflowing writes with several fragment sizes; unchanged short output; exact head/tail content; full write consumption; fixed retained capacities; split, mixed-case, scan-boundary, and discarded-middle infrastructure markers; and disabled scanning. Real finite subprocesses emit 2 MiB across stdout and stderr to verify completion without pipe deadlock, exit code 7, final summaries, staging continuation, and cancellation after overflow. No unbounded-output probe was run.
