## Delivered Behavior

- Standard Resize and S3 Put accept at most 20 MiB of encoded input. They read at most one additional byte to identify overflow, without draining the rest of an oversized reader. Read failures and cancellation do not expose a partial buffer as a successful result.
- The standard processor calls DecodeConfig before full decoding and rejects non-positive dimensions or more than 25 million pixels. Division avoids overflow in pixel accounting. GetDimensions retains header-only inspection, with bounded header reads and the same pixel policy.
- Resize rejects non-positive target bounds and clamps bounds to source dimensions before aspect-ratio arithmetic, preventing large caller bounds from overflowing output allocation dimensions. Ordinary aspect ratio, format, passthrough bytes, metadata, and JPEG quality behavior remain intact.
- Context cancellation is checked before and after input reads and between decode, scale, and encode phases. S3 also passes the context to the AWS request and uploads directly from bytes.NewReader, eliminating the extra string copy.
- The fixed limits and cancellation boundaries are documented in the image reference, package usage, Godoc, and Unreleased. Constructors, public interfaces, and S3 options remain unchanged.

## Contracts and Ownership

The shared bounded reader lives under image/internal/ingest and is available only to image adapters. The change introduces no public utility, dependency, configuration surface, background worker, or new retry policy. Input readers remain caller-owned and are not closed by either adapter.

The configuration-before-decode approach follows [Go's untrusted-image guidance](https://pkg.go.dev/image#pkg-overview). The implementation also uses standard-library limited readers; the local Go 1.26.7 and x/image v0.46.0 sources were checked for decoding and scaling behavior.

Cancellation cannot preempt an arbitrary blocked io.Reader.Read or non-context-aware codec/scaling computation. It is observed when that operation returns, and a canceled result is discarded. Callers must supply suitable I/O deadlines or cancellation-enabled readers and own concurrent processing admission. GetDimensions does not validate encoded bytes beyond the inspected header. Registered codecs must report consistent configuration and decoded dimensions.

## Resource Bounds

Encoded input reads stop at 20,971,521 bytes, including the overflow sentinel. ReadAll may retain extra slice capacity during growth; this is not a strict heap limit. S3 no longer creates another body-sized string allocation.

At 25 million pixels, an RGBA destination accounts for up to 100 MB of pixel storage and a 16-bit RGBA source can account for 200 MB. Catmull-Rom can also require a floating-point intermediate of 32 bytes per intermediate pixel, plus convolution tables and codec buffers. The input limits make these dimensions finite but do not claim a small fixed working set or whole-process memory ceiling. No large-pixel allocation or denial-of-service probe was run; oversized-image tests use only small headers.
