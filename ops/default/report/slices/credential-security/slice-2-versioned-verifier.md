## Purpose

Deliver AUTH-02's independent password-record primitive with measured, bounded
Argon2id work. Auth service and storage integration remain in Slice 3.

## Delivered Behavior

- Create standard PHC `$argon2id$v=19$m=...,t=...,p=...$salt$output` records
  with independent CSPRNG 16-byte salts and 32-byte outputs.
- Enforce canonical decimal parameters, parameter order and unpadded standard
  Base64, with a 128-byte record cap. Reject unsupported algorithms/versions,
  bcrypt, malformed fields and excessive parameters before KDF allocation.
- Normalize valid UTF-8 to NFC at creation and verification, preserving case
  and whitespace. Bound raw/normalized bytes at 4096 and normalized code points
  at 1024. New-password minimum and blocklist policy remain caller obligations.
- Distinguish mismatch, invalid record/input/configuration, busy admission and
  context failure. Failed hashing returns an empty record without secret text.
- Share bounded admission across hash and verification. Default creation is
  64 MiB, three iterations and four lanes; default concurrency is two.

## Implementation Notes

Hashing stays in `model`; the implementation uses existing `x/crypto/argon2`
and `x/text/unicode/norm` dependencies. It performs no database work and adds
no prehash, compatibility reader or rehash path. Creation settings and stored-
record acceptance ceilings are separate and immutable.

Memory limits are 19 through 256 MiB, iterations 1 through 10 and lanes 1
through 8. Below 64 MiB, at least two iterations are required. Concurrency is
1 through 16, subject to maximum memory times concurrency at most 512 MiB.
Default verification ceilings equal creation settings. The parser bounds input,
parameters, salt and output before expensive work; verification uses stored cost.

Admission is immediate: full capacity returns a classified busy error rather
than retaining a waiting queue. Context checks surround synchronous KDF work;
late results are discarded and slots are released. Argon2 cannot be interrupted,
so cancellation retains admission until derivation finishes. Owned input/output
byte slices are cleared without claiming complete managed-memory zeroization.

Tests include a fixed PHC record generated by the reference `libargon2`
implementation. It verifies under different creation settings, demonstrating
interoperability and stored-parameter use. Unicode tests exercise equivalent
NFC representations, preserved whitespace/case and 64/1024 four-byte code points.
Concurrent tests exercise shared creation/admission and two simultaneous verifies.
Parser fuzzing never invokes a KDF, even for accepted maximum-cost records.

### Measured defaults

Measurements used Go 1.27.1 on Linux amd64, AMD Ryzen 5 7430U, with
`GOMAXPROCS=4` selected by `-cpu=4`. Each benchmark has three samples of five
iterations. Record creation is outside timing. Figures are local bounded samples,
not a production capacity or tail-latency guarantee.

| Candidate memory | Iterations | Lanes | Median verification | Observed range |
| --- | --- | --- | --- | --- |
| 19 MiB | 2 | 1 | 21.21 ms | 18.80–21.52 ms |
| 64 MiB | 1 | 1 | 44.81 ms | 42.33–46.97 ms |
| 64 MiB | 3 | 1 | 114.39 ms | 108.25–121.08 ms |
| 64 MiB | 3 | 4 | 61.32 ms | 56.02–61.79 ms |

The selected profile follows the second recommended Argon2id option in
[RFC 9106 section 4](https://www.rfc-editor.org/rfc/rfc9106.html#section-4).
Its measured latency supports the stronger three-pass profile rather than the
cheaper candidates. The lower supported floor follows
[OWASP Argon2id guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#argon2id).

| Active verifications | Active KDF memory ceiling | Median batch completion | Median amortized time per verification |
| --- | --- | --- | --- |
| 1 | 64 MiB | 55.31 ms | 55.31 ms |
| 2 | 128 MiB | 126.78 ms | 63.39 ms |
| 4 | 256 MiB | 252.33 ms | 63.08 ms |

Two active operations retain a 128 MiB KDF work budget. Four do not materially
improve amortized throughput on this measurement, so the default remains two.
The budget covers active Argon2 buffers, not total process memory or Go GC-retained
allocations. Separate verifier instances/processes have separate budgets.

## Contracts Added or Changed

- `PasswordVerifierConfig` defines trusted creation cost, verification ceilings
  and bounded concurrency.
- `NewPasswordVerifier` validates per-operation and aggregate resource limits.
- `PasswordVerifier.Hash(ctx, password)` returns a PHC record or an empty result
  with an error.
- `PasswordVerifier.Verify(ctx, record, password)` returns nil on a match;
  `ErrPasswordMismatch` and `ErrPasswordRecord` classify proof/record failures.
- `ErrPasswordInput`, `ErrPasswordVerifierConfig`, `ErrPasswordVerifierBusy`
  and standard context errors classify other failures.

## Risks and Follow-ups

- Service signup/sign-in still use the existing bcrypt path until Slice 3.
  This slice alone does not enforce candidate policy or current-state storage.
- Applications must share the verifier, bound requests/attempts and choose
  deployment-specific budgets. Cancellation is not a hard KDF execution deadline.
- Parameters do not establish NIST/FIPS compliance or an application assurance
  level. Later authentication requirements remain outside this delivery slice.
- Slice 3 starts only after Slice 2 merges and integration is verified on `dev`.
